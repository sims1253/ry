# 0.9.1 stabilization

The [release tracker](https://github.com/sims1253/ry/issues/392) records the
candidate commit, CI runs, artifact checksums, and installed-product checks.
This release keeps the six existing core targets and the Rust 1.88 minimum.
The VS Code and Positron extension version is 0.9.2 and bundles core 0.9.1.
Zed's gallery version remains independent; its automatic download selects
the latest stable core release.

## Accepted fixes

The release includes performance work (#340), Actions maintenance
(#385 through #389), package function lookup (#396), the larger serialized
data cap (#393), `.data` inference (#394), the mirai contract (#399), opaque
class metadata (#395), forwarded defaults (#400), rejected default modes
(#397), and condition coercion (#398).

Release qualification also found a cyclic-data crash in `workflowsets`
(#401) and a false condition-length warning in `rstan` (#402). Both have
small regression fixtures. The decoder fix preserves the unrelated
unbound-name diagnostic; the subset fix preserves checks on index expressions.

```r
choices <- c(if (flag) "a", "b", "c")
if (choices[1L] == "a") 1L
```

A scalar subscript selects one element here. An opaque receiver cannot
justify carrying the source length into the result.

## Corpus acceptance

The committed Posit ledger contains 443 records: 37 true positives and 406
false positives. The tidyverse ledger contains 103 records: 10 true positives,
41 false positives, and 52 without an owner. Their native reconciliation
checks must pass on the release candidate.

Earlier labels were corrected with runtime evidence: function-mode lookup
invalidated two old shadowing rationales, and four renv conditions accept
valid scalar flags. The ledger notes preserve those audits. A lower count
alone is not evidence that true positives survived.

The broad comparison uses a frozen snapshot of 472 current package trees.
The original audit did not record source hashes, so the comparison cannot
claim to replay its historical 2,852 findings. The tracker records the
snapshot manifest and binary hashes, per-rule changes, new findings, and
any remaining qualification failures.

## Release checks

Follow [the release runbook](../release-runbook.md). The checksum hook now
runs each verified archive on a native runner, checks the version and an
RY040 error, then repairs the file and requires a clean check. It records
compressed and installed size separately. All six smoke jobs must pass
before the host job can publish.

Installed VSIX tests use fresh trusted and untrusted profiles. CLI/LSP
parity, parser fuzzing, and the 1,000-seed LSP session test remain separate
gates. A successful build does not substitute for those checks.
