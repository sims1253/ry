Consensus report · Plans 34–36

Measure now. Build one quality spine. Fix every surface against it.

The plans are not competitors. The durable solution is a shared correctness architecture: one project fixture, one protocol client, one cold-versus-incremental equivalence family, first-class parser invariants, and structured diagnostics.

The decision

Plan 35 supplies the architecture. Plan 34 supplies release truth and rule governance. Plan 36 consumes the architecture to repair shipped editor behavior.

Do not build the universal mutation engine or warm cache until their contracts have been validated.

North star

One fixture. Multiple execution modes. One observable contract.

Most escaped defects lived between layers. The new spine drives the same project through every public mode and compares what users actually receive—not raw internal state.

Execution

Four tracks, with real parallelism

Effort is not the constraint. Dependency clarity is. The corpus measurement must start on existing tooling and must not wait for the new protocol harness.

Track A · 0.9 truth

Fire the instrument now

  • Measured Posit re-audit and TP retention.
  • Fast PR gate; full nightly gate.
  • Per-rule R semantic-claim coverage.
  • Fix the known RY032 dead arm.
  • Prove or retract “identical filtering.”

Independent: uses today’s ecosystem tooling.

Track B · quality spine

Build and prove reusable infrastructure

  • Acyclic shared fixture/testkit seam.
  • Real JSON-RPC subprocess client.
  • Published CLI/LSP differential.
  • Fix package-metadata and file-eligibility parity.
  • R1/R6 parser and full incremental invariants.
  • Fix checker parameter-metadata propagation.
  • Structured Fix representation.
Track C · shipped correctness

Repair the remaining LSP contract

  • Per-folder settings, config and stub isolation.
  • A4 under an add/remove-folder session.
  • B1 under forced interleaving and session equality.
  • Cached baseline reload and filter precomputation.
  • Shared, visible and bounded discovery.
  • Verify Plan 35 parity and dirty propagation remain green.
Track D · depth and governance

Add breadth after contracts are real

  • Shrinkable LSP state-machine properties.
  • R7 literal-to-parameter report.
  • Targeted mutation pilots and rule verdicts.
  • Parser fuzzing using R1/R6 oracles.
  • Separately redesign complete warm-cache format.

Now: truth + spine

Run corpus measurement while protocol, parser, incremental, fixture, and structured-diagnostic work proceeds independently.

Next: deterministic oracles

Message/fix correctness, UTF-16 contracts, calibrated complexity growth, semantic-list coherence, and targeted CI-gate falsification.

Then: LSP remediation

Gate each change by the state transition it affects, not by Plan 36’s lettered group.

Finally: governance and depth

Mutation metrics only after R7 validates their usefulness; warm cache only after full cache correctness is designed.

The four concepts that do the heavy lifting

These are the reusable oracles that catch the next defect rather than preserve only the last example.

Cross-mode equivalence

The oracle catches missing channels—defaults, excludes, baselines, workspace routing and package metadata—not merely filter order.

State equivalence

Incremental final state = cold final state

→
Warm servercached mutable state
=
Fresh serversame final workspace

Use deterministic scripts for known transitions, forced scheduling for races, and property generation with shrinking for unknown sequences.

Parser preservation

R6 targets two recurring silent-data-loss bugs. Pair it with a one-time audit of parser None propagation and R1 span validity.
